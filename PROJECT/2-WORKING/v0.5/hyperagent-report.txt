# Evaluation and Architectural Assessment: Fine-Tuning `BAAI/bge-small-en-v1.5` vs. Compact Code Embedding Models on Apple Silicon

This report evaluates the technical feasibility, data constraints, training pipelines, and architectural tradeoffs of fine-tuning [`BAAI/bge-small-en-v1.5`](https://huggingface.co/BAAI/bge-small-en-v1.5) locally on Apple Silicon for semantic code retrieval across private polyglot software repositories (Python, JavaScript/TypeScript, PHP, HTML/templates, API schemas, and documentation).

## 4. Training Pipelines & Apple Silicon Feasibility

### Contrastive Fine-Tuning Pipeline Architecture

To fine-tune an embedding model (e.g., `bge-small-en-v1.5` or `CodeRankEmbed`) with hard negatives on local Apple Silicon:

```
┌────────────────────────────────────────────────────────────┐
│ 1. Triplet Mining (Local Repo + CoRNStack)                 │
│    - Anchor: Query / Docstring / Issue Prompt              │
│    - Positive: AST-extracted Function / Component Chunk    │
│    - Hard Negative: Lexical/BM25 false positive from repo  │
└────────────────────────────┬───────────────────────────────┘
                             ▼
┌────────────────────────────────────────────────────────────┐
│ 2. Contrastive Loss Computation                            │
│    - Loss: MultipleNegativesRankingLoss / InfoNCE          │
│    - Matryoshka Representation Loss (MRL) (optional)       │
│    - In-batch negatives + explicit mined negatives         │
└────────────────────────────┬───────────────────────────────┘
                             ▼
┌────────────────────────────────────────────────────────────┐
│ 3. PyTorch Execution on Apple Silicon                      │
│    - Device: `torch.device("mps")`                         │
│    - Optimization: AdamW, AMP (bfloat16/float16)           │
│    - Memory: Gradient checkpointing / PEFT LoRA            │
└────────────────────────────────────────────────────────────┘
```

### Framework Implementations

1. **Sentence Transformers (`sentence-transformers >= 3.0`)**:
   - **Loss**: `losses.MultipleNegativesRankingLoss(model=model, scale=20.0, similarity_fct=util.cos_sim)`.
   - **Data Input**: `InputExample(texts=[query, positive_code, hard_negative_code])` or `datasets.Dataset` with `(anchor, positive, negative)` columns.
   - **Hard Negative Mining**: Utilize BM25 / dense retriever to surface top-20 candidates excluding the true positive, selecting candidates with high similarity scores (>0.6) as hard negatives.
   - **Apple Silicon Compatibility**: Full native support via `device="mps"`.

2. **FlagEmbedding (`FlagOpen/FlagEmbedding`)**:
   - **Loss**: InfoNCE with Cross-Entropy Loss + Knowledge Distillation (`AbsModeling.py`).
   - **Hard Negative Mining Tool**: Native `hn_mine.py` script (`--range_for_sampling 2-200 --negative_number 15`).
   - **Distillation Support**: Distills teacher cross-encoders (e.g., `BAAI/bge-reranker-large` or `bge-code-v1`) into the small student encoder.

3. **Apple Silicon Hardware Constraints**:
   - For `bge-small-en-v1.5` (33M params): Full fine-tuning fits comfortably in <2GB VRAM on Apple Silicon Unified Memory using MPS, achieving >250 steps/sec.
   - For `CodeRankEmbed` (137M params): Full fine-tuning or LoRA (rank=16 on `q_proj`, `v_proj`, `out_proj`) consumes ~3.5GB Unified Memory on MPS with batch size 32.
   - For `Qwen2.5-Coder-1.5B` / `jina-code-1.5b`: LoRA via `peft` + `mlx` / `PyTorch MPS` consumes ~6GB Unified Memory.

## 5. Shortlist of 5 Recommended Candidates vs. Fixed Control Group

### Recommended Candidate Models

1. **`nomic-ai/CodeRankEmbed` (137M)**:
   - *Why*: State-of-the-art bi-encoder for code retrieval. 8192 context window accommodates entire classes, large multi-function modules, and schema definitions. Pretrained on 21M cleaned CoRNStack samples with native Python, JS, and PHP support.
2. **`jinaai/jina-code-embeddings-1.5b` (1.54B)** (or Q4 GGUF):
   - *Why*: Built on `Qwen2.5-Coder-1.5B`, supporting 32K context and instruction prefixes. Captures architectural questions, cross-language dependencies, and structural semantics.
3. **`codesage/codesage-small` (130M)**:
   - *Why*: Purpose-built bidirectional code encoder trained via identifier deobfuscation and function-body contrastive learning. Compact and efficient for local re-indexing.
4. **`BAAI/bge-m3` (567M)**:
   - *Why*: Combines dense vectors, sparse lexical weights, and ColBERT multi-vector scoring in a unified model with 8192 context. Natively bridges exact keyword/symbol lookup and semantic intent.
5. **Fine-Tuned `BAAI/bge-small-en-v1.5` (Custom Domain LoRA/Full)**:
   - *Why*: Tests whether domain adaptation with repository-derived triplets and CoRNStack can overcome its 512 context limit and general-text tokenizer constraints.

### Fixed Control Group Baselines

1. **Untuned `BAAI/bge-small-en-v1.5`** (Dense-only baseline, general text).
2. **Current Local Qwen Embedding Model** (e.g., `gte-Qwen2-1.5B-instruct` or `Qwen2.5-Coder`).
3. **SQLite FTS5 / BM25 Lexical Retrieval** (Lexical-only baseline using code-tokenized indices for camelCase, snake_case, and file paths).
4. **Hybrid Lexical + Dense Retrieval with Reciprocal Rank Fusion (RRF)**:
   $$\text{RRF\_Score}(d) = \sum_{m \in \{\text{Dense}, \text{FTS5}\}} \frac{1}{k + \text{rank}_m(d)} \quad (k=60)$$
5. **Cross-Encoder Reranker Stage**: Reranking top-50 hybrid candidates using [`BAAI/bge-reranker-large`](https://huggingface.co/BAAI/bge-reranker-large) or [`jinaai/jina-reranker-v2-base-multilingual`](https://huggingface.co/jinaai/jina-reranker-v2-base-multilingual).

```
│ ├── Slice 3: JS / TS Frontend Components (30 queries)                 │
│ ├── Slice 4: PHP Endpoints & Models (30 queries)                      │
│ ├── Slice 5: HTML / Blade / Twig Templates (25 queries)               │
│ ├── Slice 6: Cross-Language Bridging (PHP ↔ JS/TS) (30 queries)       │
│ ├── Slice 7: Architecture / Conceptual "How it works" (30 queries)     │
│ ├── Slice 8: Test-to-Implementation Linkage (25 queries)               │
│ └── Slice 9: Negative / "No Answer in Corpus" (20 queries)             │
└───────────────────────────────────┬────────────────────────────────────┘
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ Retrieval & Evaluation Matrix                                          │
│ ├── Candidates: 5 Shortlisted Models + 5 Control Baselines             │
│ ├── Pipeline: Dense Vector Index vs. Hybrid FTS5 + RRF + Reranker      │
│ └── Metrics: File R@5/10, Symbol R@5/10, MRR@10, nDCG@10, Latency     │
└────────────────────────────────────────────────────────────────────────┘
```

### Benchmark Query Slices (250 Total Queries)

1. **Exact Identifier / Symbol Lookup (30 queries)**:
   - Queries targeting specific classes, functions, route constants, and configuration keys (e.g., `PaymentGatewayInterface`, `handleStripeWebhook`, `AUTH_SESSION_COOKIE`).
2. **Language-Specific Deep Logic**:
   - **Python Slice (30 queries)**: Celery task workflows, SQLAlchemy ORM mappings, Pydantic schemas.
   - **JavaScript / TypeScript Slice (30 queries)**: React state management, Redux/Zustand dispatchers, API client wrappers.
   - **PHP Slice (30 queries)**: Laravel / Symfony controllers, middleware pipelines, Eloquent model relationships.
3. **HTML & Server-Rendered Templates (25 queries)**:
   - Blade/Twig/Jinja directives, component slot inclusions, DOM data attribute bindings.
4. **Cross-Language Bridging (30 queries)**:
   - "Which PHP route handles the payload dispatched by `useUserCheckout.ts`?"
   - "Where is the backend schema matching the frontend TypeScript `UserBillingProfile` interface?"
5. **Architecture & Conceptual "How does this work?" (30 queries)**:
   - "How is multi-factor authentication enforced during password resets?"
   - "Explain the lifecycle of a document export request from upload to S3 upload."
6. **Test-to-Implementation Linkage (25 queries)**:
   - Linking unit and integration test fixtures to the underlying controller or service class.
7. **Negative Control ("No Answer in Corpus") (20 queries)**:
   - Plausible developer queries for features not implemented in this repository (measuring cosine distance thresholding and false-positive suppression).

### Evaluation Metrics & Target SLA

- **File-Level Recall@5 and Recall@10**: Proportion of test cases where the target file appears in top-$k$.
- **Symbol-Level Recall@5 and Recall@10**: Target specific function/class chunks.
- **MRR@10 (Mean Reciprocal Rank)** & **nDCG@10**: Ranking quality of the primary ground-truth code unit.
- **No-Answer Precision (Negative Accuracy)**: Rejection accuracy on negative queries when maximum similarity is below threshold $\tau$.
- **Latency & Indexing Throughput**: Milliseconds per query on Apple Silicon and total corpus indexing time (chunks/second).
- **End-to-End Agent Context Success Rate**: Downstream pass rate when feeding the top-5 retrieved chunks into a coding agent to answer the developer query.

## 8. Strategic Recommendation & Decision Path

1. **Why Fine-Tuning `bge-small-en-v1.5` from Scratch is Suboptimal as a Primary Retriever**:
   - **Tokenizer Mismatch**: `bge-small-en-v1.5` uses a standard BERT WordPiece tokenizer trained on English text. It splits programming syntax, variable names (e.g., `get_user_by_id`, `useCallback`), and template directives into multiple subword fragments, diluting embedding quality.
   - **Context Window Ceiling (512 tokens)**: Real-world functions, class definitions, and route controllers regularly exceed 512 tokens. Truncating chunks discards structural context and return types.
   - **Lack of Native Code Pretraining**: General text embeddings lack exposure to programming language control flow and AST structures.

2. **The Recommended Action (Option e + c Hybrid)**:
   - **Adopt `nomic-ai/CodeRankEmbed` (137M) or `jina-code-embeddings-1.5b` as the dense foundation**: These models provide native code tokenization, 8K–32K context windows, and pretraining on multi-million code corpora across Python, JS, and PHP.
   - **Deploy a Two-Stage Hybrid Retrieval Pipeline**:
     - **Stage 1 (Hybrid Dense + Lexical)**: Run dense vector search (`CodeRankEmbed` 137M) in parallel with SQLite FTS5 (BM25) over AST chunks, fusing results with Reciprocal Rank Fusion ($k=60$).
     - **Stage 2 (Local Cross-Encoder Reranking)**: Feed the top 25–50 retrieved candidates to a compact cross-encoder reranker (such as `bge-reranker-large` or `jina-reranker-v2-base`) running locally on Apple Silicon.
   - **Repository-Specific Fine-Tuning (Optional Iteration)**:
     - If domain-specific vocabulary or proprietary API schemas require adaptation, apply LoRA fine-tuning to `CodeRankEmbed` or `Qwen2.5-Coder` using repository-mined triplets (docstring ↔ implementation and issue ↔ code diffs) via `sentence-transformers` on Apple Silicon MPS.
