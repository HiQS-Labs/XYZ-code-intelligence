# Reproducible training pipelines for fine-tuning embedding models for code search / code RAG

Scope: evidence table for someone fine-tuning **BAAI/bge-small-en-v1.5** for code retrieval on an **Apple Silicon Mac**.
Every value below comes from a page fetched in this research session (August 28, 2026). Unconfirmed values are written `n.a.`

---

## 1. Executive summary

**A reproducible pipeline does exist, but it has to be assembled from two or three parts, and one piece — LoRA on a small BERT encoder for code retrieval — has no ready-made end-to-end example.** The strongest single stack is Sentence Transformers: it documents `MultipleNegativesRankingLoss`, whose default configuration is explicitly called "the InfoNCE loss, SimCSE loss, cross-entropy loss with in-batch negatives or in-batch negatives loss" and which supports `hardness_mode` values `in_batch_negatives` / `hard_negatives` / `all_negatives` ([Sentence Transformers losses reference](https://sbert.net/docs/package_reference/sentence_transformer/losses.html)); it ships a first-class hard-negative miner, `mine_hard_negatives()`, with `range_min`/`range_max`, `max_score`, `absolute_margin`, `relative_margin`, optional `CrossEncoder` rescoring, `sampling_strategy` and `output_format` in `triplet` / `n-tuple` / `labeled-pair` / `labeled-list` ([mine_hard_negatives API](https://sbert.net/docs/package_reference/util/hard_negatives.html)); it ships retrieval evaluation with `InformationRetrievalEvaluator` reporting MRR, Recall@k, NDCG, accuracy@k, precision@k and MAP@k, plus `NanoBEIREvaluator` ([Sentence Transformers evaluation reference](https://sbert.net/docs/package_reference/sentence_transformer/evaluation.html)); and it has a **concrete PEFT/LoRA-on-an-encoder example** — a `LoraConfig(task_type=TaskType.FEATURE_EXTRACTION, r=64, lora_alpha=128, lora_dropout=0.1)` added to `sentence-transformers/all-MiniLM-L6-v2` via `model.add_adapter(...)`, trained on GooAQ with `MultipleNegativesRankingLoss`, scoring 0.4705 NDCG@10 on NanoBEIR versus 0.4728 for full fine-tuning, with an adapter of 9.44 MB = 2.14% of base weights ([Training with PEFT Adapters](https://sbert.net/examples/sentence_transformer/training/peft/README.html)). **Honest gaps:** (a) that LoRA example is on a QA dataset, not code, and the docs page does not name the runnable script file or show hard-negative mining in the same recipe, so the LoRA + hard-negatives + code-data combination must be composed by the user; (b) FlagEmbedding, the official BGE trainer, documents `use_lora`, `lora_rank`, `lora_alpha`, `target_modules`, `peft_model_path`, `save_merged_lora_model` — but its concrete LoRA configs are the decoder-only `bge-multilingual-gemma2` and `bge-en-icl` examples targeting `q_proj k_proj v_proj o_proj gate_proj down_proj up_proj`, i.e. **no published LoRA example for an encoder-only BGE such as bge-small** ([FlagEmbedding embedder fine-tuning README](https://github.com/FlagOpen/FlagEmbedding/tree/master/examples/finetune/embedder)); (c) no repository found in this session provides a Mac/MPS-specific training recipe for embedding models — Apple Silicon support is generic PyTorch MPS (macOS 12.3+, `torch.device("mps")`, training explicitly supported, backend still described by Apple as beta: [PyTorch MPS notes](https://docs.pytorch.org/docs/stable/notes/mps.html), [Apple Metal/PyTorch](https://developer.apple.com/metal/pytorch/)) with documented limitations: not all ops implemented (`PYTORCH_ENABLE_MPS_FALLBACK=1`), whole model must fit in unified memory, `bf16` requires macOS 14.0+, and the MPS graph cache grows per unique tensor shape so padded/variable-length batches can exhaust memory ([Transformers Apple Silicon guide](https://huggingface.co/docs/transformers/en/perf_train_special)); (d) the code-retrieval side is mostly **data and evaluation**, not training: CoRNStack's own training/curation code is not released ("We plan to release the full training and dataset curation code soon!", [CoRNStack repo](https://github.com/gangiswag/cornstack)), and CoIR / CodeRAG-Bench / BEIR are evaluation harnesses only; the runnable code-search *training* scripts that do exist (CodeXGLUE `run.py`, UniXcoder `run.py`) train RoBERTa/CodeBERT/UniXcoder encoders with CUDA-shaped defaults and report MRR only.

## 3. Ranked starting points for LoRA/fine-tuning BGE Small for code RAG on a Mac

1. **Sentence Transformers (trainer + `MultipleNegativesRankingLoss` + `mine_hard_negatives()` + `InformationRetrievalEvaluator`)** — the only stack where all four required pieces are documented in one framework, with `device="mps"` supported, InfoNCE semantics stated explicitly, hard negatives with margin/score filtering, and a full IR metric set (MRR, Recall@k, NDCG, MAP@k, accuracy@k, precision@k) ([training overview](https://sbert.net/docs/sentence_transformer/training_overview.html), [losses](https://sbert.net/docs/package_reference/sentence_transformer/losses.html), [mine_hard_negatives](https://sbert.net/docs/package_reference/util/hard_negatives.html), [evaluation](https://sbert.net/docs/package_reference/sentence_transformer/evaluation.html), [model reference](https://www.sbert.net/docs/package_reference/sentence_transformer/model.html)). Use `CachedMultipleNegativesRankingLoss` with a small `mini_batch_size` to get large effective batches within unified memory ([losses](https://sbert.net/docs/package_reference/sentence_transformer/losses.html)).
2. **Sentence Transformers "Training with PEFT Adapters"** — the one concrete LoRA-on-an-encoder recipe found: `TaskType.FEATURE_EXTRACTION`, `r=64`, `lora_alpha=128`, `lora_dropout=0.1`, `model.add_adapter(...)`, MNRL training, 0.4705 vs 0.4728 NDCG@10 against full fine-tuning ([PEFT training example](https://sbert.net/examples/sentence_transformer/training/peft/README.html)). Swap GooAQ for your own (query, code) pairs; add mining from step 1 yourself.
3. **CoIR (+ its MTEB integration)** — the cheapest credible *code-retrieval* scorecard: `pip install coir-eval`, 10 code datasets in BEIR/MTEB schema, Sentence-Transformers model support; run a subset (e.g. `cosqa`, `codesearchnet`) as your held-out benchmark ([CoIR](https://github.com/CoIR-team/coir)). Remember to substitute BGE's own query instruction for the `"query: "` prefix in their example.
4. **CodeRAG-Bench retrieval half** — for a *local codebase-RAG* benchmark: convert your repo into BEIR format (`corpus.jsonl`, `queries.jsonl`, `qrel/test.tsv` under `retrieval/datasets`), then use `eval_beir_sbert_canonical.py` to get NDCG/MRR/Recall/Precision at 1–1000; repository-level corpora (`repoeval_repo`, `swebench_repo`) are pre-built ([CodeRAG-Bench](https://github.com/code-rag-bench/code-rag-bench)). Caveat: no license, unmaintained since Nov 2024, Pyserini/Java needed only for BM25.
5. **FlagEmbedding** — use it for the **hard-negative mining and data contract** even if you train with Sentence Transformers: `hn_mine.py` with `--range_for_sampling 2-200 --negative_number 15`, and the `{"query", "pos", "neg", "pos_scores", "neg_scores", "prompt", "type"}` JSONL schema; its `encoder_only.base` trainer is the official BGE path, but expect CUDA/DeepSpeed assumptions and no LoRA example for encoder-only BGE ([embedder fine-tuning README](https://github.com/FlagOpen/FlagEmbedding/tree/master/examples/finetune/embedder), [finetune dir](https://github.com/FlagOpen/FlagEmbedding/tree/master/examples/finetune)).

Honorable mention for a working reference notebook flow on exactly `BAAI/bge-small-en`: the LlamaIndex guide (`SentenceTransformersFinetuneEngine`, `generate_qa_embedding_pairs`, hit rate + `InformationRetrievalEvaluator`) ([LlamaIndex guide](https://docs.llamaindex.ai/en/stable/examples/finetuning/embeddings/finetune_embedding/)) and its origin repo of three notebooks ([run-llama/finetune-embedding](https://github.com/run-llama/finetune-embedding)) — no hard negatives, no LoRA, and self-declared outdated, but the shortest end-to-end path.
