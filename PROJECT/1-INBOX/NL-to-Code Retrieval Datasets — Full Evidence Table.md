## 1. Executive summary

For **training** NL→code retrievers, the usable supply is dominated by docstring↔function pairs mined from GitHub: [CodeSearchNet](https://github.com/github/CodeSearchNet) (2M comment/code pairs, 6 languages), its filtered CodeXGLUE derivatives ([1,005,474 pairs](https://huggingface.co/datasets/google/code_x_glue_ct_code_to_text)), [The Vault](https://huggingface.co/datasets/Fsoft-AIC/the-vault-function) (34,098,775 code-text pairs across 10 languages, MIT), and [CoRNStack](https://huggingface.co/datasets/nomic-ai/cornstack-python-v1) (docstring↔code triplets with hard negatives, built from deduplicated Stack v2 with dual-consistency filtering). For **query↔code with real human relevance labels** the pool is far thinner and almost entirely Python: [CoSQA](https://github.com/Jun-jie-Huang/CoCLR) (20,604 human-annotated Bing-query/Python-code labels), [WebQueryTest](https://raw.githubusercontent.com/microsoft/CodeXGLUE/main/Text-Code/NL-code-search-WebQuery/README.md) (1,046 human-annotated pairs), and [CoSQA+](https://arxiv.org/html/2406.11589v3) (multi-choice labels produced by test-driven DeepSeek-V3 agents over CodeSearchNet Python functions). For **evaluating code RAG** the modern, qrel-bearing options are [CoIR](https://arxiv.org/html/2407.02883v3) (10 datasets, 2M+ documents, nDCG@10, BEIR/MTEB schema), [CodeRAG-Bench](https://github.com/code-rag-bench/code-rag-bench) (BEIR-format `qrel/test.tsv` plus execution-based end-to-end scoring), and issue-localization suites ([SweLoc/SWE-Bench-Lite/LocBench](https://arxiv.org/html/2505.07849v2), [Loc-Bench_V1](https://huggingface.co/datasets/czlll/Loc-Bench_V1/blob/main/README.md), and the 2026 [CORE-Bench](https://arxiv.org/html/2606.11864v1) with 180K+ queries and explicit qrels at three levels).

**PHP coverage: exists, but only in a handful of resources and almost never with retrieval-grade relevance labels.** PHP is a first-class language in [CodeSearchNet](https://huggingface.co/datasets/code-search-net/code_search_net) (one of 6 languages; [241,241 train / 12,982 valid / 14,014 test docstring pairs in the CodeXGLUE version](https://huggingface.co/datasets/google/code_x_glue_ct_code_to_text)), in [The Vault](https://huggingface.co/datasets/Fsoft-AIC/the-vault-function) (4,696,756 PHP pairs), in [CommitPack](https://huggingface.co/datasets/bigcode/commitpack) (2,555,419 PHP commit samples) and [CommitPackFT](https://huggingface.co/datasets/bigcode/commitpackft) (24,791), in [The Stack](https://huggingface.co/datasets/bigcode/the-stack), in [CommitChronicle](https://huggingface.co/datasets/JetBrains-Research/commit-chronicle), and — for issue↔code retrieval with qrels — in [CORE-Bench](https://arxiv.org/html/2606.11864v1) (PHP among 11 languages at Levels 2–3) and [SWELocMulti](https://web3.arxiv.org/pdf/2512.20482) (206 PHP repos / 4,591 PRs / 16,608 training instances). PHP is **absent** from CoSQA/CoSQA+/AdvTest/WebQueryTest (Python-only), from [CoREB](https://arxiv.org/html/2605.04615v2), and from RepoBench-Python/RepoEval/SWE-bench Lite.

**HTML/template coverage: largely a gap.** HTML is present only as raw pre-training text or commit diffs, not as labeled retrieval targets: [The Stack](https://huggingface.co/datasets/bigcode/the-stack) lists `html` among its 358 languages, [The Stack v2](https://huggingface.co/datasets/bigcode/the-stack-v2) mentions scraped HTML, [CommitPack](https://huggingface.co/datasets/bigcode/commitpack) has an `html` split (2,366,841 samples) plus `html+erb`, `html+php`, `html+django`, `html+eex` template splits, [CommitPackFT](https://huggingface.co/datasets/bigcode/commitpackft) has 20,214 HTML + 10,910 `html+erb` + 399 `html+django` + 150 `html+php` samples, and [code-rag-bench/github-repos](https://huggingface.co/datasets/code-rag-bench/github-repos) contains HTML documents in its retrieval pool. The only benchmark-with-qrels HTML signal found is [CodeFeedback-ST inside CoIR](https://arxiv.org/html/2407.02883v3), whose language list includes HTML. HTML is explicitly *not* in the language lists of [CORE-Bench](https://arxiv.org/html/2606.11864v1), [SWELocMulti](https://web3.arxiv.org/pdf/2512.20482), [The Vault](https://huggingface.co/datasets/Fsoft-AIC/the-vault-function), or [CodeSearchNet](https://huggingface.co/datasets/code-search-net/code_search_net). TypeScript is a second, smaller gap: absent from CodeSearchNet/The Vault/CoIR language lists, present in [The Stack](https://huggingface.co/datasets/bigcode/the-stack), [CommitPack](https://huggingface.co/datasets/bigcode/commitpack), [CommitChronicle](https://huggingface.co/datasets/JetBrains-Research/commit-chronicle), [CORE-Bench](https://arxiv.org/html/2606.11864v1) and [SWELocMulti](https://web3.arxiv.org/pdf/2512.20482).

**Leakage is systemic, not incidental.** CodeSearchNet is simultaneously the training corpus and the substrate for AdvTest, WebQueryTest, CoSQA+, CoIR's CodeSearchNet/CodeSearchNet-CCR, and CORE-Bench Level-1 — so any retriever trained on CSN or on The Stack (from which The Vault and CoRNStack derive) is exposed to those eval corpora. Published evidence: metrics on duplicated code corpora are ["inflated by up to 100%" versus de-duplicated corpora](https://arxiv.org/abs/1812.06469), and [inter-dataset duplication between CodeSearchNet pre-training and fine-tuning test splits produces inflated performance](https://arxiv.org/abs/2401.07930). Only a few resources document leakage controls: [RepoBench v1.1 dedups against Stack v2 file content](https://huggingface.co/datasets/tianyang/repobench_python_v1.1), [SweLoc excludes SWE-Bench/LocBench repositories and dedups by source-code overlap](https://arxiv.org/html/2505.07849v2), and [CORE-Bench's training split uses repositories disjoint from the SWE-bench family](https://arxiv.org/html/2606.11864v1).

## 3. Recommendations

### Best 3–5 for **training** NL→code retrieval

1. **The Vault (function level)** — [34,098,775 code↔docstring pairs, 10 languages, MIT licence, with 4,696,756 PHP and 1,683,568 JavaScript pairs and per-language train/valid/test splits](https://huggingface.co/datasets/Fsoft-AIC/the-vault-function). Best combination of scale, permissive licence, and non-Python coverage; deduplicated before splitting.
2. **CoRNStack (`nomic-ai/cornstack-*`)** — [ready-made `<query, positive, negative>` triplets built from deduplicated Stack v2 with dual-consistency filtering and curriculum hard negatives](https://huggingface.co/datasets/nomic-ai/cornstack-python-v1); [ICLR 2025, trained the CodeRankEmbed retriever](https://openreview.net/forum?id=iyJOUELYir). The hard negatives matter more than raw pair count for retriever quality.
3. **SWELocMulti (SweRank+) / SweLoc** — [155,663 issue→function instances across 10 languages including 16,608 PHP, with consistency filtering and hard-negative mining](https://web3.arxiv.org/pdf/2512.20482), and [SweLoc's documented exclusion of SWE-Bench/LocBench repos](https://arxiv.org/html/2505.07849v2). This is the only training signal that matches real "find the code that this bug report refers to" codebase-RAG queries.
4. **CodeXGLUE Code-to-Text (filtered CodeSearchNet)** — [1,005,474 cleaned pairs with explicit per-language splits (PHP 241,241 train)](https://huggingface.co/datasets/google/code_x_glue_ct_code_to_text). Still the standard warm-start; note the [C-UDA licence](https://huggingface.co/datasets/google/code_x_glue_ct_code_to_text) and heavy contamination.
5. **CommitPackFT (+CommitPack for scale)** — [NL-instruction↔code-edit pairs across 277/350 languages, uniquely including php (24,791) and html/html+erb/html+django/html+php](https://huggingface.co/datasets/bigcode/commitpackft). The only realistic way found to inject **HTML/template** and rich PHP signal into a retriever, after reformatting commit subjects into queries.

Supplement with **CoSQA** ([19,604 human-labeled Python query↔code training pairs](https://github.com/Jun-jie-Huang/CoCLR)) and **StaQC** ([147,546 real Stack Overflow question↔Python-code pairs, CC BY 4.0](https://github.com/LittleYUYU/StackOverflow-Question-Code-Dataset)) to shift query distribution from docstrings toward real user phrasing.

### Best 2–3 for **evaluating** code RAG

1. **CoIR** — [10 datasets, >2M documents, 8 subtasks, BEIR/MTEB-compatible qrels, nDCG@10, published leaderboard](https://arxiv.org/html/2407.02883v3) with [ready-to-load qrel files](https://huggingface.co/datasets/CoIR-Retrieval/cosqa). Use it as the fast regression harness — but discount CodeSearchNet/CodeSearchNet-CCR scores for any model trained on CSN or The Stack, and note most subsets carry [exactly 1 relevant document per query](https://arxiv.org/html/2606.11864v1).
2. **CORE-Bench** (if you can accept a 2026-fresh benchmark) — [180K+ queries with 823,345 / 52,712 / 106,479 qrels across three levels, multi-positive (10.4–41.3 relevant docs per query), 11 languages including PHP, TypeScript and JavaScript, plus a training split on repos disjoint from the SWE-bench family](https://arxiv.org/html/2606.11864v1). It is the only fetched resource that evaluates *broader-context* retrieval (docs, tests, config, call sites), which is exactly the codebase-RAG setting.
3. **CodeRAG-Bench** — [BEIR-format `qrel/test.tsv` with annotated ground-truth documents, plus execution-based end-to-end scoring and reported nDCG/MRR/Recall/Pass@1](https://github.com/code-rag-bench/code-rag-bench). Use it when you need to prove retrieval improvements translate into working code, not just better ranking.

For issue-driven retrieval specifically, add **Loc-Bench_V1** ([560 test examples spanning bug/feature/performance/security issues with function-level gold edits](https://huggingface.co/datasets/czlll/Loc-Bench_V1/blob/main/README.md)) and, for a contamination-resistant sanity check, **CoREB** ([counterfactually rewritten LiveCodeBench problems with 23,827 graded qrels](https://arxiv.org/html/2605.04615v2)).

### Hard constraints to plan around

- **HTML/templates:** no labeled retrieval benchmark exists in anything fetched. Only [CoIR's CodeFeedback-ST language list](https://arxiv.org/html/2407.02883v3) includes HTML with qrels. If HTML/template retrieval matters, you must build your own eval set — the most viable raw material is [CommitPack's html / html+erb / html+django / html+php splits](https://huggingface.co/datasets/bigcode/commitpack), [The Stack's `html`](https://huggingface.co/datasets/bigcode/the-stack), and [code-rag-bench/github-repos HTML documents](https://huggingface.co/datasets/code-rag-bench/github-repos).
- **PHP:** training data is plentiful ([The Vault](https://huggingface.co/datasets/Fsoft-AIC/the-vault-function), [CommitPack](https://huggingface.co/datasets/bigcode/commitpack), [CodeXGLUE CSN](https://huggingface.co/datasets/google/code_x_glue_ct_code_to_text), [SWELocMulti](https://web3.arxiv.org/pdf/2512.20482)); PHP *evaluation* with qrels exists essentially only in [CORE-Bench L2/L3](https://arxiv.org/html/2606.11864v1) and the [SWE-Bench Multilingual localization conversion](https://arxiv.org/html/2505.07849v2).
- **TypeScript:** absent from CodeSearchNet, The Vault and CoIR; available via [The Stack](https://huggingface.co/datasets/bigcode/the-stack), [CommitPack](https://huggingface.co/datasets/bigcode/commitpackft), [CommitChronicle](https://huggingface.co/datasets/JetBrains-Research/commit-chronicle), [CORE-Bench](https://arxiv.org/html/2606.11864v1), [SWELocMulti](https://web3.arxiv.org/pdf/2512.20482).
- **Leakage hygiene:** before trusting any headline number, dedup your training data against the eval corpora at function level — the published effect size is [up to 100% metric inflation](https://arxiv.org/abs/1812.06469) and [demonstrated inter-dataset leakage from CodeSearchNet](https://arxiv.org/abs/2401.07930). Prefer benchmarks with documented controls: [RepoBench (Stack v2 dedup)](https://huggingface.co/datasets/tianyang/repobench_python_v1.1), [SweLoc (benchmark-repo exclusion)](https://arxiv.org/html/2505.07849v2), [CORE-Bench (disjoint training repos, answer-leak filtering)](https://arxiv.org/html/2606.11864v1), [CoREB (counterfactual rewriting)](https://arxiv.org/html/2605.04615v2).
